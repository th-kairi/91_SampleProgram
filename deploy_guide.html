1. 手順書の形式と推奨運用方法

演習マニュアルや社内ドキュメントの形式について、各メディアのメリットと注意点を比較します：

形式 メリット デメリット おすすめの用途
Markdown (.md)
★原本推奨		 GitHub上で最も見やすく、IDEでも直接閲覧・Git管理できる。Qiita/Zennへの転載もワンクリック。 ブラウザ単体では生のテキスト表示になる。 リポジトリ直下に配置する原本（マスター）
単一HTML (.html)
★実習推奨		 全環境（Win/Mac/スマホ）でブラウザさえあれば100%完璧に動作。コピーボタン等のUIを完備。 テキストエディタで見るとタグが多くなる。 学生への配布・ローカル自習用マニュアル
Qiita / Zenn 一般公開が容易で、学外からの認知やポートフォリオ・実績アピールになる。 限定公開設定や機密情報管理に注意が必要。 一般公開・知見共有用
PDF 印刷や紙での提出用に向く。 コードコピー時に改行やインデントが崩れて実行エラーになるトラブルが多発。 提出書類用（プログラミング実習には不向き）
【結論】 本リポジトリでは、GitHub標準の DEPLOY_GUIDE.md をマスターとして保持しつつ、本 deploy_guide.html を同梱することで、学生全員がミスなくコマンドをコピーして演習を進められるようにしています！

2. GitHub リポジトリ作成 ＆ Releases 公開

ルートディレクトリ（91_SampleProgram）で以下のコマンドを実行し、GitHub へプッシュします：

BASH
# 1. Git初期化
git init

# 2. ファイルをステージング (.gitignore で不要ファイルは自動除外)
git add .

# 3. コミット
git commit -m "feat: initial commit of exShop Multi-Framework EC Suite"

# 4. mainブランチ設定 & リモート登録
git branch -M main
git remote add origin https://github.com/<あなたのユーザー名>/exShop-suite.git

# 5. プッシュ
git push -u origin main

GitHub Releases による学生向けパッケージ配布

  1. バージョンタグを切ってプッシュします：
    BASH
    git tag -a v1.0.0 -m "Release v1.0.0: exShop Suite"
git push origin v1.0.0
  2. GitHub リポジトリ右側の 「Releases」→「Create a new release」 を開きます。
  3. タグ v1.0.0 を選択し、以下の3つの成果物ファイルをドラッグ＆ドロップして添付します：
    • 01_Django/exShop_project.zip (Django版演習パッケージ)
    • 02_Flask/exShop_flask.zip (Flask版演習パッケージ)
    • 03_Servlet/target/exShop.war (Servletビルド成果物)
  4. 「Publish release」 をクリックして公開します。

3. AWS EC2 インスタンスの準備 ＆ 初期構築

推奨インスタンス構成

  • AMI: Ubuntu Server 22.04 LTS または 24.04 LTS (x86_64)
  • インスタンスタイプ: t3.small または t3.medium 推奨 (メモリ2GB以上)
  • セキュリティグループ: ポート 22 (SSH), 80 (HTTP), 443 (HTTPS) を開放

EC2 への SSH 接続と共通パッケージ一括インストール

BASH (EC2)
sudo apt update && sudo apt upgrade -y

# 共通ツールのインストール (Git, Nginx, Python3, JDK 17, Tomcat 10, PostgreSQL)
sudo apt install -y git nginx curl build-essential     python3-pip python3-venv python3-dev libpq-dev     openjdk-17-jdk tomcat10 postgresql postgresql-contrib

# リポジトリのクローン
cd /var/www
sudo git clone https://github.com/<あなたのユーザー名>/exShop-suite.git
sudo chown -R ubuntu:ubuntu /var/www/exShop-suite
cd /var/www/exShop-suite

4. 各システムのデプロイ手順

① Django 版のデプロイ (Gunicorn + Systemd)

BASH (EC2)
cd /var/www/exShop-suite/01_Django/exShop

# 仮想環境の作成とライブラリ導入
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# 静的ファイルの集約 & DBマイグレーション & サンプルデータ投入
python manage.py collectstatic --noinput
python manage.py migrate
python manage.py load_sample_data

# Gunicorn の systemd サービス定義を作成
sudo bash -c 'cat <<EOF > /etc/systemd/system/exshop-django.service
[Unit]
Description=Gunicorn daemon for exShop Django
After=network.target

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/var/www/exShop-suite/01_Django/exShop
ExecStart=/var/www/exShop-suite/01_Django/exShop/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 exShop.wsgi:application

[Install]
WantedBy=multi-user.target
EOF'

# サービスの起動と自動起動登録
sudo systemctl daemon-reload
sudo systemctl start exshop-django
sudo systemctl enable exshop-django
sudo systemctl status exshop-django

② Flask 版のデプロイ (Gunicorn + Systemd)

BASH (EC2)
cd /var/www/exShop-suite/02_Flask

# 仮想環境の作成とライブラリ導入
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

# 初期データの投入
python seed.py

# Gunicorn の systemd サービス定義を作成
sudo bash -c 'cat <<EOF > /etc/systemd/system/exshop-flask.service
[Unit]
Description=Gunicorn daemon for exShop Flask Nordic
After=network.target

[Service]
User=ubuntu
Group=www-data
WorkingDirectory=/var/www/exShop-suite/02_Flask
ExecStart=/var/www/exShop-suite/02_Flask/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:5000 run:app

[Install]
WantedBy=multi-user.target
EOF'

# サービスの起動と自動起動登録
sudo systemctl daemon-reload
sudo systemctl start exshop-flask
sudo systemctl enable exshop-flask
sudo systemctl status exshop-flask

③ Servlet 版のデプロイ (Tomcat 10 + WAR)

BASH (EC2)
cd /var/www/exShop-suite/03_Servlet

# 1. PostgreSQL の作成と初期化
sudo -u postgres psql -c "CREATE USER postgres WITH PASSWORD 'postgres';"
sudo -u postgres psql -c "CREATE DATABASE exshop_db OWNER postgres;"
PGPASSWORD=postgres psql -U postgres -h localhost -d exshop_db -f sql/schema.sql
PGPASSWORD=postgres psql -U postgres -h localhost -d exshop_db -f sql/data.sql

# 2. Maven による WAR ビルド
./.tools/maven/apache-maven-3.9.9/bin/mvn clean package -DskipTests

# 3. Tomcat 10 の webapps ディレクトリに配置
sudo cp target/exShop.war /var/lib/tomcat10/webapps/exShop.war
sudo chown -R tomcat:tomcat /var/lib/tomcat10/webapps/exShop.war

# 4. Tomcat 10 の再起動
sudo systemctl restart tomcat10
sudo systemctl status tomcat10

5. Nginx による 1台での同時公開設定

1台の EC2 インスタンス（ポート80）で、3つのシステムすべてにリバースプロキシする Nginx 設定です：

BASH (EC2 Nginx 設定)
sudo bash -c 'cat <<EOF > /etc/nginx/sites-available/default
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;

    client_max_body_size 50M;

    # Django 版へのルーティング (/django/)
    location /django/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }

    # Flask 版へのルーティング (/flask/)
    location /flask/ {
        proxy_pass http://127.0.0.1:5000/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }

    # Servlet 版へのルーティング (/servlet/)
    location /servlet/ {
        proxy_pass http://127.0.0.1:8080/exShop/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }

    # デフォルトアクセス (Django版)
    location / {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;
    }
}
EOF'

# Nginx 構文チェック & 反映
sudo nginx -t
sudo systemctl reload nginx
アクセス確認:
ブラウザで http://<EC2のパブリックIP>/django/, http://<EC2のパブリックIP>/flask/, http://<EC2のパブリックIP>/servlet/ にアクセスすると、それぞれのデザインで美しく動作します！
